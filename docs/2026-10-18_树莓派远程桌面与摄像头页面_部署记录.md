## 二、⭐ 关键事实：桌面是真的，靠的是 labwc 的 "无头输出"

这是整件事里最容易搞错的一环，实测数据如下。

```bash
$ wlr-randr
NOOP-1 "Headless output 2"
    Enabled: yes
    Modes:
      1920x1080 px (current)
    Position: 0,0
    Scale: 1.000000
```

```bash
$ wayvnc -L debug   # 手动跑，看它抓了什么
Info: Capturing output NOOP-1
Info: >> Headless output 2 1920x1080+0x0 Power:UNKNOWN
```

```bash
# 用 RFB 003.003 握手问 5900 拿到的 ServerInit
✅ 帧缓冲 = 1920 x 1080
   像素格式: bpp=32 depth=24 big_endian=0 true_color=1
   桌面名 = 'WayVNC'
```

**⇒ 树莓派的 labwc（rpd-labwc）在没有任何 HDMI 显示器时，自己创建了一个虚拟输出
`NOOP-1`（1920×1080）。** 所以：

- **不接显示器也能有完整的 1920×1080 桌面**，wayvnc 抓的就是这个输出
- **`hdmi_force_hotplug=1` 根本不需要**（本次实验里加了它，但 DRM 侧
  `card1-HDMI-A-1 = disconnected`、`modes` 全空、dmesg 仍报
  `vc4-drm: Cannot find any crtc or sizes` —— **和加之前完全一样**）
- **⚠️ 别被 `modes` 为空骗了**：那是 DRM 连接器的状态，而画面来自 Wayland 合成器的虚拟输出，两者不是一回事

## 三、⚠️ 一次误判（方法论教训，报告里可写）

**错误结论：** "内核没有显示模式 ⇒ wayvnc 没有画面可抓 ⇒ 浏览器里看到的不是真桌面。"

**错在哪：**

1. 只看了 `/sys/class/drm/card*-*/modes`（DRM 层）就推断 Wayland 层没有输出
   —— 应该直接问合成器（`wlr-randr`），而不是绕三层去猜
2. 自己的探测脚本有 bug：声明了 RFB **3.8** 却在读 `SecurityResult` 时判断错位置，
   把 4 字节读歪后一直等不到 `ServerInit`，于是误以为服务器"没有帧缓冲"
3. 手动起 `wayvnc` 时绑地址失败（`trying address 0.0.23.13` → `Cannot assign requested address`），
   **这个失败是我的调用方式问题，不是服务的问题**

**正确做法：**

- 问 Wayland 要输出 → `wlr-randr`（或 `wayland-info`）
- 问 VNC 要尺寸 → 用 **RFB 003.003** 握手，客户端发完 `RFB 003.003\n` 后
  读 **32 位的 security type**，确认非 0 就直接发 4 字节 `shared` 标志，
  然后 24 字节 `ServerInit` 里前 4 字节就是 `width(2)+height(2)`
- **一个探测失败不等于服务坏了** —— 先怀疑探测脚本

## 七、摄像头页面（`07_pi_webcam.py`）

| 路由 | 作用 |
|---|---|
| `/` | HTML：左边 MJPEG 视频流，右边 top-3 概率条，每秒刷新 |
| `/stream` | `multipart/x-mixed-replace` JPEG 流 |
| `/api` | JSON：`top` / `ms` / `fps` / `frames` / `err` / `src` |
| `/health` | `{"ok":true}` |

**设计要点：**

- **纯标准库**，不用 Flask（少一个依赖、少一个坑）
- 摄像头缺失时**不崩**，返回 `err` 并在页面上显示 `NO CAMERA`
- `--test-pattern` 模式可在**没有摄像头**时用合成图验证整条链路

**实测（2026-10-18，合成图模式）：**

```
top: [["paper", 0.757], ["cardboard", 0.192], ["trash", 0.031]]
推理 47.0 ms
```

**⇒ 抓帧 → resize(BILINEAR) → int8 推理 → JSON 这条链在 Pi 上跑通，只差物理摄像头。**

## 九、⚠️ 工具使用教训：Windows 上 `ssh` 传多行命令会坏

**本机（PowerShell 5.1 / OpenSSH 9.5p2）实测：**

```powershell
# ❌ 这样会坏 —— 多行字符串被 Windows 的参数拼接收成单行，bash 报
#    "unexpected EOF while looking for matching quote" 或把后续命令当 echo 的参数
ssh pi@host "多行脚本..."
```

**✅ 正确做法（本次全程验证可靠）：**

```powershell
# 1. 本地用 write 工具写 .sh（保证 LF 换行）
# 2. 传上去
scp -o BatchMode=yes 脚本.sh niyoujia@192.168.1.66:~/
# 3. 远程把 CRLF 去掉再执行
ssh -o BatchMode=yes 192.168.1.66 "sed -i 's/\r$//' ~/脚本.sh && bash ~/脚本.sh"
```

`sed -i 's/\r$//'` 这一步不能省 —— 否则 bash 会报 `$'\r': command not found`。
