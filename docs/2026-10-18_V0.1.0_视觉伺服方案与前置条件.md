## 1. 一句话结论

**用摄像头代替编码器控制这台臂，可行，精度到厘米级；实现方式不是"识别手臂姿势"，而是"识别末端标记（ArUco）"。**

理由：同类型玩具臂（OWI-535）上已有学术实现 CRAVES 证明"单目视觉控制无编码器玩具臂"成立，但它付了三个数据集 + 6.73M 参数姿态网络的代价；ArUco 用 5 行 OpenCV 拿到同样的 6DoF 位姿，**零训练、零标注**。

## 6. 三条技术路线对比

| | A. 姿态估计（CRAVES 路线） | **B. ArUco 标记（推荐）** | C. 手眼标定 + 运动学 |
|---|---|---|---|
| 核心 | 训练网络从图像估计关节角/关键点 | OpenCV 检测标记，直接出 6DoF 位姿 | `calibrateHandEye` 求相机↔机器人变换 + 正逆运动学 |
| 需要标注数据 | **数百张，逐张标 5 个关节** | **不需要** | 不需要（但要标定板） |
| 需要标定 | 不需要 | 只需要相机内参（一次） | **需要精确手眼标定** |
| 精度 | 关键点 5–10 px → 厘米级误差 | **亚像素** | 理论最高，但依赖标定质量 |
| 工作量 | **周级到月级** | **今天下午能跑通检测** | 天级 |
| 对 2 线直流臂的适配 | 差（臂本身重复性差） | **好**（闭环修正，不依赖绝对模型） | 差（需要可信的关节角，而我们没有） |
| 判定 | 不采用 | **✅ 采用** | 不采用 |

**为什么 C 不行**：手眼标定要求你能命令臂到**已知的、可复现的关节角**。2 线直流 + 时间开环做不到这一点 —— 给定脉冲长度，落点每次都不一样。**没有可信的关节角，标定就无从建立。**

**为什么 B 行**：ArUco 给的是**末端相对相机的实际位置**，闭环是"看到在哪 → 还差多少 → 动一点 → 再看"。它**不需要知道关节角**，正好绕过 2 线直流的弱点。

**⚠️ 补充件**：[`cjiang2/planar_arm`](https://github.com/cjiang2/planar_arm) 实现了 **Uncalibrated Visual Servoing（UVS）** —— 图像空间直接映射到关节空间，**连手眼标定都省了**。如果 ArUco 闭环收敛不好，这是 B 计划的升级版。

## 7. 推荐架构

```
┌─────────────────────────────────────────────────────────┐
│ 笔记本 / 树莓派（Python 3）                                │
│                                                          │
│  ① 相机采集  cv2.VideoCapture(0)          ← 笔记本摄像头   │
│         ↓                                                │
│  ② 标记检测  cv2.aruco.ArucoDetector                      │
│      - 夹爪贴 1 个标记 → 得末端位姿 T_end                 │
│      - 目标贴/或直接用颜色框定 → 得目标位姿 T_goal         │
│         ↓                                                │
│  ③ 误差计算  e = T_goal⁻¹ · T_end   (6 维或只用 xyz)      │
│         ↓                                                │
│  ④ 控制律  增量式：Δu = K · e  （K 小步长，防超调）        │
│      - 死区补偿：小于最小脉冲时给 dither 或跳过            │
│         ↓                                                │
│  ⑤ 串口协议  文本行： "M <joint> <pulse_ms> <dir>\n"      │
│              回执：      "OK <elapsed_ms>\n"              │
└─────────────────────────────────────────────────────────┘
                          ↓ USB / UART
┌─────────────────────────────────────────────────────────┐
│ STM32（HAL，你熟）                                        │
│  ⑥ 解析指令 → H 桥 PWM 驱动 2 线直流电机                   │
│  ⑦ 定时器产生精确脉冲宽度（时间开环）                       │
│  ⑧ 回执 + 超时保护                                        │
└─────────────────────────────────────────────────────────┘
```

**关键设计决定**：

1. **相机在笔记本上，不在 Pi 上** —— 今晚就能开始，不用等 CSI 摄像头到货。验证通了再搬。
2. **闭环频率不需要高** —— 捕获+检测+串口往返约 100–150 ms（≈7–10 Hz）。**每次只走一小步，等它停稳再拍下一张**，不要连续 PID。
3. **只用位置误差（xyz），先不管姿态** —— 抓取只需要"到那个点上"，夹爪朝向靠机械限位/初始姿态保证。
4. **STM32 只做"给定关节 + 给定脉冲 = 转多久"** —— 所有视觉决策留在上位机。这样 STM32 代码极小，好调试。

## 9. 验收标准（可量化，不是"看起来能动"）

| 级别 | 判据 | 意义 |
|---|---|---|
| **门槛** | 标记检测稳定运行 ≥ 30 s，位姿抖动 < 3 mm（静止时） | 感知可信 |
| **达标** | 闭环把末端送到目标点，**重复 10 次，落点分布在直径 3 cm 的圆内** | 厘米级，够分拣 |
| **优秀** | 落点分布 **< 1.5 cm**，且单次收敛 < 5 s | 够放进小盆 |
| 失败 | 落点散布 > 6 cm 或不收敛 | 换舵机臂 |

**⚠️ 我判断"达标"（3 cm）能达成，"优秀"（1.5 cm）有风险。** 风险来源见 §10。

## 10. 风险与对策

| 风险 | 机理 | 对策 |
|---|---|---|
| **5 轴累积背隙** | 每级齿轮间隙叠加，反向运动时末端"空走"一段 | 只朝一个方向逼近目标（不来回修正）；或记录背隙补偿量 |
| **直流低速死区** | 脉冲太短电机根本不转；转起来又猛地一动 | 设最小有效脉冲（实测标定）；短距离用"点动"多次 |
| **闭环频率低（7–10 Hz）** | 拍一帧要 100–150 ms | 小步长 + 等停稳再拍；不要连续 PID |
| **电压跌落** | 电池/电源带不动 5 个电机同时转 | 用独立电源；一次只动一个关节 |
| **标记被遮挡** | 夹爪转到背面，标记看不见 | 用 `DICT_4X4_50` 多贴 2 个不同 ID 的标记，任一见即可 |
| **光照变化** | 反光/阴影影响检测 | 固定光源；用 `cv2.aruco` 的 `CORNER_REFINE_SUBPIX` |

## 12. 结论与下一步

**没有现成的"摄像头看臂 → STM32 驱动 2 线直流"整套方案。** 1,748 个仓库里，最接近的三个（CRAVES / Trash-Sorting-Robot / xarm6）都是**特定硬件 + 特定栈**，不能直接搬。

**但有完整的三层积木，组装成本是"几天"，不是"几周"**：

1. **标记检测层** —— OpenCV 的 `cv2.aruco`，成熟到不需要自己写
2. **控制层** —— 增量式误差修正，几十行
3. **执行层** —— STM32 定时器 + H 桥，你的强项

**下一步（按依赖顺序）**：

- [ ] 装 `opencv-contrib-python`，生成并打印一个 `DICT_4X4_50` 标记，验证检测（**不需要机械臂，今晚/明天就能做**）
- [ ] 翻零件盒确认 H 桥（明天）
- [ ] 装配 Cebek，逐个关节手动确认能转（明天）
