# STM32 固件 · Cebek C-9895.2 机械臂控制台

寄存器级（不用 HAL）的 Keil 工程：ILI9341 彩屏 + 四个按键 + 菜单状态机，
通过 USART2 把 3 字节指令发给树莓派，由树莓派做 USB 主机送进原厂接口板。

**编译状态**：`0 Error(s), 0 Warning(s)`，Code 7380 B / RO 1984 B / RW 72 B / ZI 2384 B，
产出 `new/CebekArm.hex` 26,593 B。Keil MDK-ARM AC5（V5.06 update 5）。

---

## 一、硬件连接

| 从 | 到 | 说明 |
|---|---|---|
| 机械臂原厂接口板 USB | 树莓派 USB 口 | 树莓派才是 USB 主机 |
| **Nucleo 的 micro-USB** | 树莓派 USB 口 | 一根线同时给板子供电 + 提供 `/dev/ttyACM0` |
| 机械臂 `BKR` | 6 V 电源 | **绝对不要从树莓派的 USB 取电给电机** |
| 扩展板上的屏与按键 | Nucleo | 已在你 Wellspan 板上焊好 |

树莓派 4B 有 4 个 USB 口，够用。

## 二、引脚分配

来源：你 Wellspan Health Watch 的 `tft-lcd` 工程（已在实物上验证）。

| 功能 | 引脚 | 复用 |
|---|---|---|
| LCD SCK | **PA5** | AF5 (SPI1) |
| LCD MOSI | **PA7** | AF5 (SPI1) |
| LCD DC | **PA11** | 通用输出 |
| LCD RST | **PA12** | 通用输出 |
| 按键 UP | **PA0** | 输入 + 上拉 |
| 按键 DOWN | **PA4** | 输入 + 上拉 |
| 按键 OK | **PB1** | 输入 + 上拉 |
| 按键 BACK | **PC13** | 输入 + 上拉 |
| 串口 TX | **PA2** | AF7 (USART2) |
| 串口 RX | **PA3** | AF7 (USART2) |

- LCD 没有 CS、没有背光脚（板上直接拉死），驱动里也就不需要。
- **PA11/PA12 同时是 L476 的 USB_DM/DP**，这块板子把它们给了 LCD，所以
  **本板不能再用 L476 的原生 USB**。这正是"机械臂必须由树莓派当 USB 主机"的物理原因。

## 三、按键操作

每个键都有短按和长按，8 个功能，不用翻菜单：

| 键 | 短按 | 长按（>500 ms） |
|---|---|---|
| **UP** | 上一个关节 | 时长 +1 档 |
| **DOWN** | 下一个关节 | 时长 −1 档 |
| **OK** | 按当前时长动一次 | **按住一直动，松开即停** |
| **BACK** | 切换方向 正/反 | **急停** |

时长档位：50 / 100 / 150 / 200 / 300 / 500 / 750 / 1000 / 1500 / 2000 / 3000 ms。
上电默认选中"肩部、正转、300 ms"。

**爪内灯**单独占列表里的 `LED` 一项，短按 OK 按当前方向开或关。

├────────────────────────────────┤

├────────────────────────────────┤

⚠️ **屏幕上只有英文**：`font_data.h` 里只有 8×16 的 ASCII 字模。
要显示中文得另做字模表，这一版没做。

⚠️ **屏幕只显示 `EST` 累计时间，永远不显示角度**——这台臂没有任何位置反馈，
把"时间"当"角度"显示就是编数据。

## 五、三层安全机制

这台臂的特性是**发一条命令就一直动，直到下一条命令**。所以刹车必须有冗余：

| 层 | 谁 | 条件 | 动作 |
|---|---|---|---|
| 1 | STM32 | 单次动作超过 **3000 ms** | 强制发 `00 00 00`，按下模式也同样受限，必须松手才能再来 |
| 2 | STM32 | 串口 **1500 ms** 收不到 `PONG` | 立刻停，并且**禁止再启动**任何动作 |
| 3 | 树莓派 | 链路 **1500 ms** 没有新命令 | 看门狗自己发 `00 00 00` |

第 2 层是关键：链路断了以后 STM32 自己发不出有效指令，只有树莓派还能刹车；
反过来树莓派整个挂掉时，STM32 会立刻发现并停止发令。
**两道保险互为对方的失效场景。**

另外：`arm_init()` 在上电时发的第一条命令就是 `00 00 00`，
防止臂在别处被驱动过、一上电就乱动。

## 六、和树莓派的线协议

ASCII 文本行，一插上就能重新对齐（不怕丢半个帧）：

| 方向 | 内容 |
|---|---|
| STM32 → Pi | `ARM <b0> <b1> <b2>`　三个十六进制字节，如 `ARM 41 00 00` |
| STM32 → Pi | `PING`　每 500 ms 心跳 |
| STM32 → Pi | `STOP`（急停时另有 `ARM 00 00 00`） |
| Pi → STM32 | `OK` / `PONG` / `ERR <原因>` / `TMO`（树莓派看门狗触发） |

波特率 115200 8N1，走 ST-LINK 虚拟串口，树莓派上是 `/dev/ttyACM0`。

树莓派侧程序：`../pi/cebek_bridge.py`

```bash
cd ~/Desktop/CebekArm
python3 cebek_bridge.py --port /dev/ttyACM0 -v
```

## 八、为什么不做"STM32 直接用 GPIO 模拟 USB"

| 硬指标 | 数值 |
|---|---|
| USB Low Speed 位宽 | **666.7 ns/bit** |
| L476 @ 80 MHz 每 bit 可用周期 | **53 个** |
| 允许边沿抖动 | **±10 ns ≈ ±0.8 个时钟周期** |

而且 USB 不是"拉高拉低"：每包要 NRZI 编码 + 位填充、CRC5/CRC16、
SETUP/DATA/ACK 三段握手（对端 165 ns 内应答）、主机每 1 ms 必发 SOF。
**GPIO 翻转做不到，没有可用开源实现。**

两条真正可行的"STM32 独立控制"路线 → 留给 V2：

| 方案 | 硬件 | 工作量 | 代价 |
|---|---|---|---|
| **MAX3421E**（SPI 转 USB 主机芯片） | ¥20–40 模块 | 约 400 行 | 推荐；不占 PA11/PA12 |
| L476 自带 OTG_FS 做主机 | ¥0 | 周级（自写主机协议栈） | PA11/PA12 与 LCD 冲突，要改板 |

## 九、改代码时的注意

1. **不要从 CubeMX 重新生成** —— 这个工程是纯寄存器手写的，没有 `.ioc`。
2. `board_pins.h` 是唯一改引脚的地方，改完不用动别处。
3. LCD 初始化那段寄存器序列是从你已点亮的工程里搬过来的，**别随手改成网上通用表**。
4. 若发现屏幕方向反了（上下颠倒），改 `lcd.c` 里的 `MADCTL_180`：
   `0xC8`（180°）/ `0x08`（0°）/ `0x68`（90°）/ `0xA8`（270°）。
5. 若 PC13（BACK 键）一直读 0，说明板上是下拉接法，
   把 `keys.c` 里 `KEY_BACK_PULL` 改成 `GPIO_PULL_NONE`。
