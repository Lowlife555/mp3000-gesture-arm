# Cebek C-9895.2 机械臂控制台

把一台 **Cebek C-9895.2** 桌面机械臂，从"只能用它自带的 Windows 软件"变成
**用 STM32 的彩屏和四个按键控制**，并顺带获得一个**树莓派上的手动控制台**。

> 这台机械臂其实是 **OWI Robotic Arm Edge (OWI-535)** 的贴牌版本。
> 识别依据：USB 设备 ID `1267:0000`（`0x1267` 是 OWI Inc. 的厂商号）、
> 5 个直流减速电机 + 爪内灯、无任何位置反馈、行程参数与 OWI 手册一致。
> 本目录不含任何原厂二进制文件或反编译产物。

## 它能做什么

| 能力 | 说明 |
|---|---|
| **独立控制台** | STM32L476 + 2.4" 彩屏 + 4 个按键，不接电脑就能选关节、选方向、选时长、开灯、急停 |
| **按住即动** | 按住按键机械臂持续运动，**松手立刻停** |
| **定时点动** | 按设定的毫秒数动一次（50–3000 ms，11 档），适合做重复实验 |
| **实时状态** | 屏上显示链路状态、当前方向/时长、每个关节的**命令累计时间** |
| **树莓派手动台** | `cebek_oneclick.py`：双击图标即开，自动连接，拔插自动重连 |
| **三层刹车** | STM32 硬上限 + 链路丢失即停 + 树莓派看门狗，互为对方的失效场景 |

## 硬件连接

```
        ┌──────────────┐
        │  6 V 电源     │   ← BKR 接口，绝不从 USB 取电给电机
        └──────┬───────┘
               │
        ┌──────▼───────┐
        │ 原厂接口板    │   5 个电机 + 爪内灯
        └──────┬───────┘
               │ USB（Low Speed 1.5 Mbit/s）
        ┌──────▼───────────────────┐
        │ 树莓派 4B                 │
        │  口1 ← 机械臂             │
        │  口2 ← Nucleo（供电+串口）│
        └──────┬───────────────────┘
               │ /dev/ttyACM0   115200 8N1，ASCII 行协议
        ┌──────▼───────┐
        │ STM32L476 +  │
        │ 彩屏 + 四键   │
        └──────────────┘
```

**三根线**：机械臂 USB → 树莓派；Nucleo 的 micro-USB → 树莓派；6 V → 原厂接口板。

### 引脚分配（STM32L476RGTx）

来源：作者前一项目 `wellspan-health-watch` 的 `tft-lcd` 工程，已在实物上验证。

| 功能 | 引脚 | 复用 |
|---|---|---|
| LCD SCK | PA5 | AF5 (SPI1) |
| LCD MOSI | PA7 | AF5 (SPI1) |
| LCD DC | PA11 | 通用输出 |
| LCD RST | PA12 | 通用输出 |
| 按键 UP / DOWN / OK / BACK | PA0 / PA4 / PB1 / PC13 | 输入 + 上拉 |
| 串口 TX / RX | PA2 / PA3 | AF7 (USART2) |

> ⚠️ **PA11/PA12 同时是 L476 的原生 USB_DM/DP**。这块板子把它们给了 LCD，
> 所以本板用不了 STM32 自己的 USB —— 这正是"机械臂必须由树莓派当 USB 主机"的物理原因。

## 架构：为什么是 STM32 + 树莓派

```
STM32  = 手和眼：按键、彩屏、状态机、安全计时，全部本地实时
树莓派 = 嘴和耳：唯一能当 USB 主机的一方，把 3 个字节送进接口板
```

**这不是偷懒。** 让 STM32 自己当 USB 主机有三条路，代价都很难看：

| 方案 | 结论 |
|---|---|
| GPIO 位翻转模拟 USB 主机 | **不可行**（见下表） |
| L476 内置 OTG_FS 做主机 | 电气成立且支持 Low Speed，但 **PA11/PA12 与 LCD 冲突要改板**，还要自写全套 USB 主机协议栈（周级工作量，调试几乎无线索） |
| 外加 MAX3421E（SPI→USB 主机芯片） | **可行**，¥20–40 模块，约 400 行。留作 V2 |

### 为什么 GPIO 模拟 USB 做不到

| 硬指标 | 数值 |
|---|---|
| USB Low Speed 位宽 | **666.7 ns/bit** |
| L476 @ 80 MHz 每 bit 可用周期 | **53 个** |
| 允许边沿抖动 | **±10 ns ≈ ±0.8 个时钟周期** |

USB 也不是"拉高拉低"：每包要 **NRZI 编码 + 位填充**、**CRC5/CRC16**、
**SETUP / DATA / ACK 三段握手**（对端 165 ns 内必须应答）、主机每 **1 ms 必发 SOF**。
在 GPIO 上做 USB **device** 有成熟先例（V-USB），但那是 AVR 用汇编卡死时序；
做 **host** 要和真实设备双向握手，难度高一个数量级，**没有可用开源实现**。

## 通信协议

### 机械臂侧（USB control transfer）

3 个字节，位打包：

```
byte0  [1:0] 夹爪   [3:2] 腕部   [5:4] 肘部   [7:6] 肩部
byte1  [1:0] 底座
byte2  bit0  爪内灯（Search Light）

每个 2 位字段： 00 = 停   01 = 正转   10 = 反转
底座：         00 = 停   01 = CW     10 = CCW
```

**传输方式**（本机实测确认）：

```
bmRequestType = 0x40   bRequest = 0x06
wValue        = 0x0100 wIndex   = 0
payload       = 3 字节
```

- 设备为 **USB Low Speed**，接口类 `0xFF`，**只有一个 `0x81` interrupt IN 端点，
  没有 OUT 端点** ⇒ bulk OUT 物理上不可能，**control transfer 是唯一通路**。
- **语义关键**：一条命令发出后机械臂**持续运动**，直到下一条命令把它改掉。
  **`00 00 00` 是通用停止帧。** "延时"完全在主机侧，机械臂内部没有计时器。
  ⇒ 所以必须有第三方在通信中断时踩刹车，见[三层安全机制](#三层安全机制)。

### STM32 ↔ 树莓派（ASCII 行协议）

| 方向 | 内容 |
|---|---|
| STM32 → Pi | `ARM <b0> <b1> <b2>`　三个十六进制字节，如 `ARM 41 00 00` |
| STM32 → Pi | `PING`　每 500 ms 心跳 |
| STM32 → Pi | `STOP` |
| Pi → STM32 | `OK` / `PONG` / `ERR <原因>` / `TMO`（树莓派看门狗触发） |

用文本行而不是二进制帧，因为串口会热插拔：**文本行一插上就能重新对齐，丢半个帧不会永久错位。**

## 快速开始

### 树莓派侧

```bash
# 1) 授权 USB 访问（只需一次，然后拔插一次机械臂）
sudo bash 授权USB访问.sh

# 2) 手动控制台（双击 机械臂控制台.desktop 也行）
python3 cebek_oneclick.py
python3 cebek_oneclick.py --selftest     # 不开窗口，只验证 USB 与协议

# 3) 串口桥（给 STM32 用）
python3 cebek_bridge.py --port /dev/ttyACM0 -v
```

`cebek.py` **不依赖 pyusb / pyserial / 虚拟环境**，只用 Python 标准库的
`ctypes` 直接调 `libusb-1.0`。Debian 上只需 `libusb-1.0-0` 这一个系统包。

### STM32 侧

1. 用 Keil MDK-ARM（AC5）打开 `stm32/CebekArm.uvprojx`
2. 编译（本目录验证结果：**0 error / 0 warning**，Code 7380 B）
3. 下载 `stm32/new/CebekArm.hex`
4. 上电后屏幕应显示 **`LINK DOWN !`（红色）** —— 这是对的，桥还没跑
5. 在树莓派上启动 `cebek_bridge.py`，1.5 s 内变成 **`LINK OK`（绿色）**

> 第 4→5 步的变化，正好证明第二层安全（链路检测）是活的。

## 按键操作

每个键都有短按和长按，8 个功能，不用翻菜单：

| 键 | 短按 | 长按（> 500 ms） |
|---|---|---|
| **UP** | 上一个关节 | 时长 +1 档 |
| **DOWN** | 下一个关节 | 时长 −1 档 |
| **OK** | 按当前时长动一次 | **按住一直动，松开即停** |
| **BACK** | 切换方向 正/反 | **急停** |

时长档位：50 / 100 / 150 / 200 / 300 / 500 / 750 / 1000 / 1500 / 2000 / 3000 ms。
上电默认：肩部、正转、300 ms。爪内灯在列表里单独占一项 `LED`。

## 三层安全机制

这台臂"发一条命令就一直转"，靠齿轮箱打滑限制行程，**没有限位开关、没有位置反馈**。
所以刹车必须冗余：

| 层 | 谁 | 触发条件 | 动作 |
|---|---|---|---|
| 1 | STM32 | 单次动作 > **3000 ms** | 强制发 `00 00 00`；按住模式同样受限，必须松手才能再来 |
| 2 | STM32 | 串口 **1500 ms** 收不到 `PONG` | 立刻停，**并禁止再启动**任何动作 |
| 3 | 树莓派 | 链路 **1500 ms** 没有新命令 | 看门狗自己发 `00 00 00` |

**第 2 层和第 3 层互为对方的失效场景**：STM32 挂了，树莓派还能刹车；
树莓派挂了，STM32 立刻发现并停发。任何单点故障都不会让机械臂带着最后一条命令一直跑。

另外 `arm_init()` 上电发的第一条命令就是 `00 00 00`。

## 已知限制

诚实清单，不粉饰：

1. **没有任何位置反馈**，所以屏上只显示 `EST`（命令累计时间），**永远不显示角度**。
   把时间当角度显示就是编数据。
2. **屏幕只有英文**：`font_data.h` 里只有 8×16 ASCII 字模，没做中文字库。
3. **位置会漂**：开环控制 + 齿轮箱回差 + 电池电压下降都会让"同一段毫秒数走的距离"变化。
   做重复性实验前应先稳定电源（台式稳压电源，而不是电池）。
4. **依赖树莓派**：STM32 单独无法驱动机械臂（原因见上）。
5. **单关节控制**：一次只驱动一个关节（虽然协议本身支持多电机并发）。
6. **USB 主机能力未做**：MAX3421E 方案是 V2，不在本目录。

### 首次上板可能遇到的两件事

- **屏幕上下颠倒** → 改 `stm32/lcd.c` 的 `MADCTL_180`：
  `0xC8`(180°) / `0x08`(0°) / `0x68`(90°) / `0xA8`(270°)
- **BACK 键（PC13）读不到** → 板上若是下拉接法，把 `stm32/keys.c` 的
  `KEY_BACK_PULL` 改成 `GPIO_PULL_NONE`

## 安全声明

⚠️ 这是一个**开环**机械臂控制项目，请自行评估风险：

- 电机堵转**不会**被软件保护（只有齿轮箱打滑）。长时间堵转会烧电机或驱动器。
- **6 V 必须来自独立电源（`BKR` 接口），绝不能从树莓派或 Nucleo 的 USB 取电。**
- 这条命令是**锁存**的：直接断电、SSH 断线、程序崩溃都可能让机械臂保持最后的动作。
  **离开前请先按「全部停止」。**
- 首次运行请把机械臂**空载、悬空、远离面部和线缆**，先验证每个关节的转向是否符合预期。
- 作者不对因使用本代码造成的设备损坏或人身伤害承担责任。
