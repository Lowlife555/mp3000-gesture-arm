## 2. Q1 的歧义（必须澄清，不能替他圆）

我的题是：

```python
counts = {"fist": 0, "palm": 0}
for i in range(3):
    counts["fist"] += 1
print(counts["fist"], counts["palm"])
```

正确输出是 `3 0`（**两个**值，中间一个空格）。他答「**打印30**」。

- 如果他指的是「打印 3 和 0」→ **正确**，Python 阅读能力确认。
- 如果他指的是「打印字符串 "30"」→ 说明他把 `print(a, b)` 的**两个参数**看成了一个数。

⚠️ **两种解释都说得通，我不替他选。** 已单独提问确认。
（`print(3, 0)` 的屏幕输出长得就像 `3 0`，写成「30」很可能是省略空格，但仍需一句确认。）

## 4. 本次 grill 最大的意外收获：Q7 的真根因

> 他的原话：「第一次训练的时候我开了 Windows 摄像头的工作室效果，导致它一直跟着我的脸变焦，
> 最后导致采集的图全都有我的脸。」

**Windows Studio Effects 的「自动取景」会把脸保持在画面中心** →
中间那个 ROI 方框里装的**永远是脸**，手举到哪儿都进不去。

- 我此前的诊断（「手在框外」+「模型走亮度捷径」）是**症状与机制**，成立；
- **这条才是根因**。两者互补，不冲突。
- ⚠️ **它是个"软件开关"，可能现在还开着** → 不关掉就重采，会**以完全相同的方式再失败一次**。

已落盘的修正：
- [01_capture.py](01_capture.py)：启动打印 8 行警告 + 画面常驻黄字提醒
- [07 §5.1](07_操作清单.md)：插入「★ 真正的根因」+ 官方关闭路径 + 验证方法
- [08 §5.2](08_零基础教程_原理与技术栈.md)：插入根因 + 方法论结论

**关闭路径**（[Microsoft Learn 官方文档](https://learn.microsoft.com/en-us/training/modules/windows-studio-effects/3-how-to-use)）：
① 任务栏右下角点 **网络/音量/电池** 图标 → **Studio Effects** 磁贴 → 关
② **设置 → 蓝牙和其他设备 → 摄像头 → 选前置摄像头 → 关闭 Studio Effects**
③ 面板内有 **Reset effects** 恢复默认
**验证**：头左右移动，画面**不应该**跟着变焦。
