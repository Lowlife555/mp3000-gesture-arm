## 3. 采集数据的要点（决定明天会不会翻车）

**每类至少 200 张，最好 500 张。** 采集时刻意做这些变化：

- 手离摄像头 **30cm / 50cm / 80cm** 各采一些；
- 手在方框里 **偏左 / 居中 / 偏右**；
- **开灯 / 关灯**；
- 手心正对镜头 / 稍微侧一点。

理由：模型只会认它见过的东西。如果采集时只有一种光照和距离，明天现场灯光一变就会失灵。

## 4. 网络结构（你要能自己讲出来）

```
输入 64×64 灰度图
  → 卷积 16×3×3 + ReLU → 2×2 最大池化        找边缘、局部笔画
  → 卷积 32×3×3 + ReLU → 2×2 最大池化        把笔画拼成"手指的排布"
  → 卷积 48×3×3 + ReLU → 2×2 最大池化        更抽象的部件
  → 展平 → 全连接 64 + ReLU → Dropout 0.3    组合成判据
  → 全连接 3 + Softmax                       输出三个类别概率
```

**三个必须能讲清的概念：**

1. **卷积核**：一个小窗口在图上滑动，学的是"局部模板"。浅层学到边缘，深层把边缘组合成手指的形状。
2. **池化**：每 2×2 取最大 → 图变小，图像稍微平移也不影响判断（平移不变性）。
3. **Softmax**：把三个分数压成加起来等于 1 的概率；训练就是让正确类别的那个概率越来越大。

**训练的三个关键机制（老师可能会追着问）：**

| 机制 | 一句话解释 | 不做会怎样 |
|---|---|---|
| **损失函数**（交叉熵） | 衡量"预测概率分布"和"正确答案"差多远 | 没有优化目标 |
| **反向传播 + 梯度下降** | 从损失往回算每一层的责任，按梯度调参数 | 网络学不会 |
| **数据增强**（随机旋转/缩放/平移） | 每轮把训练图随机变一下，逼模型学形状而不是背像素 | 数据少时严重过拟合 |
| **Dropout 0.3** | 训练时随机丢掉 30% 神经元，防止死记 | 过拟合 |
| **验证集 + 早停** | 留 20% 数据从不参与训练，用它判断什么时候停 | 无法诚实地知道真实水平 |

## 6. 局限与下一步（主动说，别等他问）

**这个 demo 的局限：**
- 只有 3 类手势、几百张图，规模远小于真实任务；
- 对光照和背景仍然敏感（虽然 ROI 裁剪缓解了一部分）；
- 没有做超参数搜索、没有交叉验证，准确率数字不能过度解读。

**要变成能撑起 7000 词技术报告的 YZ3 项目，还需要补：**

| 要补的 | 为什么 |
|---|---|
| **更多类别 + 更大数据量**（或换成公开的 Speech Commands / Kaggle 数据集） | 3 类几百张撑不起"系统性工作" |
| **严格的评估方法**（k-fold 交叉验证、留出测试集、错误分析） | 评分表看重"评估诚实性" |
| **端侧部署**：TFLite Micro / CMSIS-NN 跑在 STM32L476 上，实测延迟、Flash、RAM | 这就是把 YZ3 从"软件包"升级成"嵌入式系统"的那一环，也是工作区标为最大短板的地方 |
| **与传统方法的 baseline 对比**（HOG + SVM，或决策树） | 有对比才叫实验，不然只是"跑通了一个模型" |

> EN: "The interesting part for me is not the accuracy — it is the deployment path. Conventional methods such as HOG plus SVM are a fair baseline; the real question is what a learned model buys you once it has to run on a Cortex-M with 1 MB of flash."
> 🇨🇳 我关心的不是准确率，而是部署这条路径。HOG+SVM 这类传统方法是公平的 baseline；真正的问题是——当模型必须跑在只有 1 MB Flash 的 Cortex-M 上时，学习型模型到底换来了什么。
